# راهنمای اتوماسیون: از ویدیوی تلگرام تا قسمت‌های آماده اینستاگرام

این راهنما برای همان گردش‌کاری است که انتخاب کردی:

- فایل ویدیو را از تلگرام گرفته‌ای و روی سیستم خودت داری.
- صدای ویدیو واضح است، پس متن مستقیم از **گفتار** استخراج می‌شود؛ دیگر لازم نیست از روی هاردساب انگلیسی OCR بگیری.
- ترجمه فعلاً می‌تواند توسط دستیار در چت انجام شود. مسیر API هم آماده است تا هر وقت کلید گرفتی، بدون تغییر کد خودکار شود.
- پردازش را می‌توانی روی **GitHub Actions** یا **Google Colab** انجام بدهی.
- نقطه‌های برش را سیستم از روی مکث‌ها پیشنهاد می‌دهد و **تو قبل از ساخت خروجی تأییدشان می‌کنی**.

## تصویر کلی

```text
ویدیو
  │
  ├─ مرحله 01: آماده‌سازی
  │    ├─ تشخیص گفتار → زیرنویس زبان مبدأ
  │    ├─ ترجمه با API اگر کلید باشد، وگرنه قالب آماده برای ترجمه دستی/دستیار
  │    └─ پیشنهاد برش‌ها از روی مکث، سکوت و پایان جمله
  │
  ├─ بازبینی تو
  │    ├─ ترجمه یا نمونه‌خوانی فارسی
  │    └─ جابه‌جا/حذف/اضافه‌کردن نقطه‌های برش
  │
  └─ مرحله 02: خروجی نهایی
       ├─ چسباندن فارسی بالای انگلیسی سوخته
       ├─ نسخه کامل
       └─ قسمت‌های جدا برای ریلز/شورتس
```

> **ویدیو را داخل خود درخت کد ریپو Commit نکن.** گیت برای فایل‌های ویدیویی بزرگ مناسب نیست. برای مسیر گیت‌هاب از لینک مستقیم/درایو یا فایل پیوست Release استفاده می‌کنیم.

---

## هشدار مهم درباره عمومی‌بودن ریپو

اگر ریپو **Public** باشد، فایل‌های Release و خروجی‌های پردازش می‌توانند برای دیگران قابل مشاهده یا دانلود باشند. قبل از آپلود ویدیو انتخاب کن:

1. **ریپو را Private کن** و بعد از مسیر GitHub Actions استفاده کن؛ یا
2. از **Colab** استفاده کن و ویدیو را مستقیم همان‌جا آپلود کن؛ یا
3. اگر عمومی‌بودن فایل برایت مسئله‌ای نیست، Release عمومی بساز.

کلید API را هرگز داخل کد، فایل کانفیگ، Issue یا چت ننویس. محل درستش GitHub Secrets یا Colab Secrets است.

# مسیر A: GitHub Actions

## راه‌های رساندن ویدیوی تلگرام به گیت‌هاب اکشنز

### گزینه ۱: لینک گوگل‌درایو یا لینک مستقیم

فایل را در گوگل‌درایو آپلود کن، دسترسی اشتراک‌گذاری را روی **Anyone with the link** بگذار و لینک را در ورودی `video_url` وارد کن.

لینک مستقیم فایل و بعضی لینک‌های پلتفرمی مثل YouTube و Dailymotion هم پشتیبانی می‌شوند؛ اما بعضی پلتفرم‌ها دانلود خودکار را مسدود می‌کنند. اگر خطای 403 گرفتی، از فایل محلی خودت با درایو، Release یا Colab استفاده کن.

### گزینه ۲: پیوست Release در همان ریپو

1. در ریپو به بخش **Releases** برو.
2. **Draft a new release** را بزن.
3. یک تگ تازه و ساده بساز، مثلاً:

   ```text
   input-bunny-001
   ```

4. عنوانی مثل `Input - Bunny 001` بنویس.
5. فایل ویدیو را به قسمت پیوست‌ها بکش و رها کن.
6. Release را منتشر کن؛ می‌توانی گزینه **Pre-release** را هم فعال کنی.
7. نام دقیق فایل ویدیو و تگ را نگه دار؛ در هر دو ورک‌فلو لازم می‌شوند.

بعداً می‌توانی فایل فارسی نهایی و فایل برش تأییدشده را به **همین Release** اضافه کنی تا مرحله دوم خودش پیداشان کند.

## مرحله 01: آماده‌سازی زیرنویس و پیشنهاد برش‌ها

1. در ریپو به زبانه **Actions** برو.
2. از فهرست سمت چپ، این ورک‌فلو را انتخاب کن:

   **01 آماده‌سازی زیرنویس و پیشنهاد برش‌ها**

3. دکمه **Run workflow** را بزن.
4. فقط یکی از دو روش ورودی ویدیو را پر کن:
   - `video_url`؛ یا
   - هر دو مورد `release_tag` و `asset_name`.
5. بقیه ورودی‌های مهم:

   | ورودی | پیشنهاد |
   |---|---|
   | `job_name` | نام کوتاه و ثابت، مثل `bunny-001`؛ در مرحله دوم هم دقیقاً همین را بنویس. |
   | `source_language` | زبان واقعی گفتار: `en`، `zh`، `ja`، `ko` یا `auto`. زبان هاردساب را ملاک قرار نده؛ زبان صدا مهم است. |
   | `whisper_model` | روی GitHub اول `small`؛ اگر خطا زیاد بود `medium`. مدل‌های بزرگ روی CPU گیت‌هاب کندند. |
   | `translation_mode` | `auto` بگذار. اگر کلید API نباشد قالب دستی ساخته می‌شود؛ اگر بعداً کلید اضافه شود خودکار ترجمه می‌کند. |
   | `part_target` | پیش‌فرض ۹۰ ثانیه. |
   | `part_min` / `part_max` | پیش‌فرض ۴۵ تا ۱۵۰ ثانیه تا برش بتواند خودش را به مکث طبیعی برساند. |

6. اجرا را شروع کن و صبر کن تا تمام شود.
7. پایین صفحه اجرای تمام‌شده، Artifactای با نامی شبیه این را دانلود کن:

   ```text
   subtitle-prep-bunny-001
   ```

### داخل Artifact چه هست؟

| فایل | کاربرد |
|---|---|
| `*.source.srt` | متن استخراج‌شده مستقیم از گفتار ویدیو |
| `*.fa.srt` | اگر API فعال بوده ترجمه فارسی؛ وگرنه قالبی با زمان‌بندی آماده و متن زبان مبدأ |
| `*.cuts.suggested.txt` | پایان پیشنهادی قسمت‌ها، همراه با مکث و آخرین دیالوگ |
| `NEXT_STEPS_FA.md` | راهنمای کوتاه همان کار |

Artifactها در این تنظیمات ۳۰ روز نگه داشته می‌شوند؛ فایل نهایی را روی سیستم خودت هم ذخیره کن.

## بازبینی ترجمه

### فعلاً بدون API

فایل `*.fa.srt` را که قالب است برای ترجمه بده. قانون مهم:

- فقط متن خطوط فارسی شود؛
- شماره خطوط و زمان‌ها تغییر نکنند؛
- اسم شخصیت‌ها در کل فایل یکدست باشند؛
- جمله‌ها کوتاه و مناسب خواندن سریع زیرنویس باشند.

می‌توانی فایل `*.source.srt` یا همان قالب را در چت برای دستیار بفرستی و فایل فارسی نهایی را تحویل بگیری.

### بعداً با API

وقتی کلید گرفتی، هیچ تغییری در کد لازم نیست:

1. در ریپو برو به **Settings → Secrets and variables → Actions**.
2. **New repository secret** را بزن.
3. نام را دقیقاً این بگذار:

   ```text
   OPENAI_API_KEY
   ```

4. مقدار کلید را فقط در همان فرم گیت‌هاب وارد کن.
5. مرحله 01 را با `translation_mode=auto` اجرا کن.
6. در صورت نیاز `translation_model` و `translation_api_base` را برای سرویس سازگار با OpenAI خودت تغییر بده.

حتی وقتی ترجمه با API انجام می‌شود، قبل از رندر نهایی اسم‌ها، عددها، جمله‌های منفی و چند خط تصادفی را نمونه‌خوانی کن.

## بازبینی و تأیید برش‌ها

فایل `*.cuts.suggested.txt` شبیه این است:

```text
00:01:24.300  # پایان قسمت 1 — مکث ~2.1 ثانیه؛ پایان جمله؛ آخرین دیالوگ: «...»
00:03:05.800  # پایان قسمت 2 — مکث ~1.4 ثانیه؛ آخرین دیالوگ: «...»
```

هر خط یعنی «اینجا یک قسمت تمام شود». قسمت آخر همیشه تا پایان ویدیو ادامه دارد و خط جدا نمی‌خواهد.

می‌توانی:

- زمان یک خط را جلو یا عقب ببری؛
- یک خط را پاک کنی تا دو قسمت یکی شوند؛
- خط تازه اضافه کنی؛
- توضیحات بعد از `#` را نگه داری یا پاک کنی؛ خوانده نمی‌شوند.

فرمت‌های قابل قبول زمان:

```text
83.4
1:23
00:01:23.400
۰۰:۰۱:۲۳
```

الگوریتم پیشنهاد برش سه نشانه را ترکیب می‌کند:

1. فاصله بین پایان یک زیرنویس و شروع زیرنویس بعدی؛
2. سکوت واقعی صدا با FFmpeg `silencedetect`؛
3. پایان جمله با نشانه‌هایی مثل `.`، `!`، `؟` و `…`.

اگر موسیقی پس‌زمینه بلند باشد، سکوت واقعی کم پیدا می‌شود؛ در این حالت مکث بین دیالوگ‌ها نشانه اصلی است.

## رساندن فایل فارسی و برش تأییدشده به مرحله دوم

یکی از این سه روش را انتخاب کن:

### روش پیشنهادی: همان Release ورودی

Release ویدیو را ویرایش کن و این دو فایل را هم پیوست کن:

```text
bunny-001.fa.srt
bunny-001.cuts.suggested.txt
```

مهم است نام فایل فارسی با `.fa.srt` تمام شود و نام فایل برش کلمه `cuts` و پسوند `.txt` یا `.json` داشته باشد. مرحله دوم وقتی همان `release_tag` را بدهی، خودش آن‌ها را پیدا می‌کند.

### روش دوم: آپلود فایل‌های کوچک داخل ریپو

فایل SRT و برش سبک‌اند و می‌توانی از **Add file → Upload files** داخل مسیری مثل زیر بگذاری:

```text
jobs/bunny-001/bunny-001.cuts.txt
```

بعد در مرحله دوم همین مسیرها را در `fa_srt_path` و `cuts_path` بنویس.

### روش سوم: لینک

لینک مستقیم یا لینک اشتراکی درایو فایل‌ها را در `fa_srt_url` و `cuts_url` بده.

## مرحله 02: ساخت خروجی نهایی و قسمت‌ها

1. در **Actions** این ورک‌فلو را انتخاب کن:

   **02 ساخت خروجی نهایی و قسمت‌ها**

2. **Run workflow** را بزن.
3. همان ورودی ویدیوی مرحله اول را دوباره بده.
4. `job_name` را دقیقاً همان نام مرحله اول بگذار.
5. اگر فایل فارسی و برش در همان Release نیستند، URL یا مسیرشان را پر کن.
6. تنظیمات مهم:

   | ورودی | پیشنهاد |
   |---|---|
   | `make_full=true` | نسخه کامل هم ساخته شود. برای تست سریع یا ویدیوی خیلی بلند می‌توانی موقتاً خاموشش کنی. |
   | `split_mode=pause` | فقط وقتی استفاده می‌شود که فایل برش تأییدشده پیدا نشود. |
   | `position=above_english` | فارسی بالای انگلیسی سوخته می‌ماند و هر دو دیده می‌شوند. |
   | `preset=veryfast` | برای CPU گیت‌هاب عملی‌تر است. |
   | `crf=21` | تعادل مناسب کیفیت و حجم. |

7. وقتی اجرا تمام شد، در خلاصه Run لینک یک Release تازه با تگی شبیه `outputs-...` می‌بینی.
8. از همان Release فایل‌های MP4 قسمت‌ها، نسخه کامل، `manifest.json` و `captions.txt` را دانلود کن.

> ساخت هم‌زمان نسخه کامل و همه قسمت‌ها یعنی ویدیو عملاً بیش از یک بار انکود می‌شود. برای یک ویدیوی ۹۰دقیقه‌ای روی CPU گیت‌هاب ممکن است طولانی شود یا به سقف زمانی برسد. اگر این اتفاق افتاد، اول `make_full=false` و `preset=ultrafast` را امتحان کن، یا رندر را در Colab/سیستم خودت انجام بده.

# اجرای محلی با خط فرمان

اگر خواستی روی سیستم خودت یا سرور دیگری اجرا کنی:

## ۱. ساخت زیرنویس از گفتار

```bash
fa-subs transcribe video.mp4 \
  --language zh \
  --whisper-model small \
  --out video.source.srt
```

`--language` باید زبان واقعی صدا باشد. برای تشخیص خودکار بنویس `auto`، ولی انتخاب صریح زبان معمولاً مطمئن‌تر است.

## ۲. پیشنهاد برش‌ها

```bash
fa-subs suggest-cuts video.mp4 \
  --srt video.source.srt \
  --out video.cuts.suggested.txt \
  --target 90 \
  --min-duration 45 \
  --max-duration 150
```

## ۳. حالت auto برای ترجمه

```bash
fa-subs run video.mp4 \
  --provider auto \
  --split-mode pause \
  --part-duration 90 \
  --part-min-duration 45 \
  --part-max-duration 150
```

رفتار `auto` عمداً دوحالته است:

- اگر متغیر محیطی کلید API وجود داشته باشد، ترجمه خودکار انجام می‌شود؛
- اگر وجود نداشته باشد، در ایستگاه ترجمه دستی می‌ایستد و قالب فارسی + برش‌های پیشنهادی می‌سازد.

## ۴. رندر با فارسی و برش تأییدشده

```bash
fa-subs run video.mp4 \
  --fa-srt video.fa.srt \
  --cuts video.cuts.suggested.txt
```

وقتی `--cuts` داده شود، همان زمان‌های تأییدشده دقیقاً استفاده می‌شوند؛ حتی اگر طول قسمت‌ها با هم متفاوت باشند.

| Whisper زبان را اشتباه تشخیص داده | `source_language` را صریح و مطابق صدا بگذار؛ زبان زیرنویس سوخته ملاک نیست. |
| گفتار کم است و ASR جمله‌های خیالی ساخته | این ویدیو برای مسیر ASR مناسب نیست. روی نمونه کوتاه تست کن؛ اگر دیالوگ واقعی واضح نیست، باید از OCR هاردساب استفاده شود. |
| برش‌ها زیاد یا کم هستند | `part_target` و بازه `part_min` تا `part_max` را تغییر بده و دوباره پیشنهاد بگیر. برای قسمت‌های طبیعی بلندتر، بازه را پهن‌تر کن. |
| مرحله دوم فایل فارسی را پیدا نمی‌کند | نام فایل باید با `.fa.srt` تمام شود، یا مسیر/URL دقیقش را در ورودی بده. |
| مرحله دوم برش تأییدشده را پیدا نمی‌کند | نام فایل Release باید شامل `cuts` و پسوند `.txt`/`.json` باشد، یا مسیر/URL مستقیم بده. |
| فارسی روی انگلیسی افتاده | در مرحله دوم `margin_v` را بیشتر کن و فقط یک اجرای آزمایشی کوتاه بگیر. |
| اجرای گیت‌هاب خیلی طول کشید | در آماده‌سازی مدل کوچک‌تر انتخاب کن؛ در رندر `make_full=false` و `preset=ultrafast` را امتحان کن یا از Colab استفاده کن. |
| کلید API کار نمی‌کند | نام Secret باید دقیقاً `OPENAI_API_KEY` باشد و مدل/آدرس API با همان سرویس سازگار باشند. مقدار کلید را در لاگ یا چت ننویس. |
